# 更改 2026-07-26：Gameplay Lab 实验协议定稿

## 为什么改

联网和正式日记界面还没有接入，但这不应阻止我们先判断世界是否值得观察。新的实验协议让研究者在幕后手动输入外部五维，每次只推进一天；玩家只面对草原、天气和痕迹，不会看到情绪数值或快进按钮。

协议最重要的作用是把“输入当天的响应”和“世界经过一天后的自主变化”分开。这样后续看到脚印、积水或动物留下的痕迹时，可以判断它属于哪一个阶段，而不是把两次模拟混成一次即时反馈。

没有新增生产数据、存档字段或世界写者。

## 验证

1. 对照 `WorldManager.OnJournalSubmitted()`：协议记录了 catch-up → 注入 → 当前日响应式模拟 → 世界/日记存盘。

4. 对照 `SaveSystem`：未提议任何 JSON 格式变化，Debug Log 不持久化到世界存档。
5. 本批仅文档，无 C# 或场景修改；未执行编译和 Play 验证。

# 追加：Gameplay Lab 控制器落地（提案 20260726-03）

## 为什么改

实验者现在只需在 Inspector 调整外部五维，然后点击一次命令，世界便经过恰好一天。玩家不会看到文本、向量或快进操作，只会看到一天之后草原留下了什么。

原协议把输入和 Tick 分成两个操作，会让研究流程变重；若直接组合正式 `OnJournalSubmitted` 与 `WorldTick`，又会在一次按钮中模拟两遍世界。最终批准的 `20260726-03` 改为 `InjectEmotion → WorldTick(1)`，保留惯性和单日生态模拟，同时把文本固定为实验占位符。

## 改动清单

| 文件 | 改动 |
|---|---|
| `Assets/GlimmerDiary/Scripts/Utils/ManualGameplayLab.cs` | 实现五维 Inspector、单日向量 Tick、无输入自主 Tick、固定占位 JournalEntry、WorldSave 持久化、协议保护和 `[GameplayLab:v2]` 单行日志 |
| `Assets/GlimmerDiary/Scripts/Utils/ManualGameplayLab.cs.meta` | 保留用户创建脚本时生成的稳定 Unity GUID |
| `Docs/GameplayLabLrotocol.md` | 升级为 `gameplay-lab/2`；记录 01/02 被取代、03 已批准，并以单按钮单日周期替换旧 Submit/Tick 状态机 |
| `Docs/InteractionWorksheet.md` | 回填最终实验周期与提案状态 |

## 数据和所有权

| 数据/动作 | 单一写者 | 读取者 |
|---|---|---|
| Inspector 五维 | 研究者 | `ManualGameplayLab` 当前 Tick 方法 |
| 临时 `EmotionVector` / 占位 `JournalEntry` | `ManualGameplayLab` 当前方法 | `EmotionInertiaSystem` / `SaveSystem` |
| `E_env` | `EmotionInertiaSystem` | L2、L3、Gameplay Lab 日志 |
| `gameTime` | `WorldManager.WorldTick` | 世界系统、Gameplay Lab 日志 |
| Debug Log v2 | `ManualGameplayLab` | 研究者 |

控制器不直接写世界字段，不改变 WorldManager、Data 类型或 JSON 格式。

## 周期语义

```text
有输入：Inspector 五维 → InjectEmotion → WorldTick(1) → 验证 → SaveWorldState → AppendJournalEntry
无输入：WorldTick(1) → 验证 → SaveWorldState
```

- 一次命令只调用一次 `WorldTick`，因此只运行一次 `SimulatePass`。
- 输入周期 `gameTime +1`、`emotionHistory +1`。
- 自主周期 `gameTime +1`、`emotionHistory +0`。
- 占位文本固定为 `[manual gameplay lab]`，不影响世界。
- Tick 前后使用方法局部基线，不保留样本或 active input。

## 已知限制

1. `world_state.json` 与 `journal_log.json` 是两个非原子文件；第二次写入失败时控制器进入 Invalid 并禁止重试，但无法自动回滚。
2. `WorldEnvironmentState` 的部分积分状态仍不在存档中；POST_TICK 日志是当时运行状态，不代表重启后全部恢复。
3. 本批只完成脚本和协议，尚未修改场景；自动注入器和 runOnStart tester 的禁用仍需单独场景计划与批准。

## 验证

1. `dotnet build Assembly-CSharp.csproj --no-restore`：0 error，6 个既有 warning。
2. 代码审查确认输入周期仅调用一次 `InjectEmotion`、一次 `WorldTick(1)`、一次世界保存和一次 Journal 追加；自主周期不注入、不追加 Journal。
3. 不变量检查已放在持久化之前；日期或历史增量异常不会被 Lab 主动写入磁盘。
4. Unity 资产刷新后生成工程已指向新脚本路径；组件尚未接入场景，因此 Context Menu、Console 和真实 Play 周期验证仍待场景批次完成。

# 追加二：撤销 Gameplay Lab 过度工程，改用 ManualTicking

## 为什么改

玩法实验只需要研究者调整五维并让世界经过一天。session、cycle、状态机、结构化日志和数百行防御代码没有帮助玩家看懂草原，反而阻碍了最核心的试验动作。

新的 `ManualTicking` 只保留两个动作：带当前向量推进一天，或不带输入让世界自主推进一天。世界仍使用既有惯性、自然时钟、模拟顺序和 SaveSystem。

## 改动清单

| 文件 | 改动 |
|---|---|
| `Assets/GlimmerDiary/Scripts/Utils/ManualGameplayLab.cs(.meta)` | 删除被设计者否决的过度工程控制器 |
| `Assets/GlimmerDiary/Scripts/Utils/ManualTicking.cs(.meta)` | 补全用户起草的最小控制器；修正文件名与类名不一致，保留原 meta GUID；增加 Tick 后存盘、占位 Journal 追加和无输入 Tick |
| `Docs/GameplayLabLrotocol.md` | 协议缩减为 `gameplay-lab/3`，只规范五维字段、两个 Tick 命令和现有接口顺序 |
| `Docs/InteractionWorksheet.md` | 指向最终最小控制器 |

## 所有权

没有新增世界字段或写者。`ManualTicking` 只构造临时 `EmotionVector/JournalEntry`，世界状态仍由现有 L2 系统写入，文件仍只由 SaveSystem 写入。

## 验证

1. Unity 刷新后 `Assembly-CSharp.csproj` 只引用 `ManualTicking.cs`，文件名与 MonoBehaviour 类型一致。
2. `dotnet build Assembly-CSharp.csproj --no-restore`：0 error；共 13 个既有 warning，其中 Assembly-CSharp 6 个，其余来自本机 MCP 工程。
3. 本批未挂载组件、未执行真实 Tick，因此没有修改世界存档。
