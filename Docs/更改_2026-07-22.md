# 更改 2026-07-22：旱 droughtDebt + T1 土堆水毁态（Batch 2）

> 依据：`Docs/交互设计工作台_2026-07-21_矩阵补全.md` §5.5 第 2 行（旱，后续优先级 2）+ §5.1 雨→田鼠行（T1 土堆第四老化态「水毁」，2026-07-21 定稿）。
> 实施：Claude，auto mode。

## 为什么改

1. **旱作为机制不存在**：世界只有水位每日 −0.03 的被动消退，长期无雨没有累积后果。矩阵定稿：droughtDebt 累积状态 + 三阈值，旱是"雨→生命"整张表的反向总开关。
2. **雨毁巢穴无痕迹**：田鼠被水淹搬走后，旧土堆永远崭新。矩阵定稿：T1 土堆加第四老化态「水毁」——zone 湿度 >0.8 时塌陷湿泥态，不可逆锁存，与 T2 塌洞分工（水毁是痕迹的状态，塌洞是地貌的疤）。

## 玩家视角

长期不下雨：低洼水面一寸寸退；动物脚印越来越密地踩向河岸；旱得狠了地表裂开。再下雨：裂缝消失，但被泡透的土堆塌成湿泥、永远留着。

## 改动清单

| 文件 | 改动 |

| `Core/AnimalDriveSystem.cs` | debt>0.6：狐狸觅食/田鼠扩张目标向 riverbank 偏置（涌现：河岸 T3 脚印加密）；TickTree vitality 目标封顶当前值（恢复停滞） |
| `Core/AnimalDriveTuning.cs` | `droughtConvergeThreshold=0.6`、季节基准雨表、droughtK 等可调参数 |

## 边界与纪律

- droughtDebt 不进存档（与 env 8 字段一致），重启按当前 E_env/季节重积
- 心跳/启动路径只 ConsumeSignals 不积 debt（不违拆分纪律）
- debt 数值永不暴露给玩家——只见裂缝、脚印密度、水退、枯黄（Batch 4）
- 旱的「枯黄」表达显式留给 Batch 4 草色通路
- **已知限制**：T1 水毁锁存是 session 内 HashSet（L3 只读纪律，binder 不能写世界状态）——玩家当场看着被泡的土堆本 session 内永不复原；跨 session 的不可逆性由两条确定性路径覆盖：湿度仍 >0.8（重判）或存在 vole_relocate_flood 历史记录（被泡搬家=泡过的证据）。湿度刚好在 session 间隙回落且非洪水搬家的边角情形会"复原"——若 playtest 觉得刺眼，需要 L2 湿度极值记录（新状态，属设计决策，留给设计者拍）
- k 定为 0.05（矩阵未给数值）：无雨秋季 20 天过 0.3、40 天过 0.6；0.02 需 100 天，超 90 天 catch-up 上限永远触发不了

## 验证

1. 离线编译 0 错
2. 旱链端到端：压 V 使 Rainfall≈0 → Simulate 快进 30+ 天 → debt 爬升 → 水面退 → 动物向 riverbank 集中 → 河岸 T3 加密 → debt>0.6 地裂出现
3. 雨季恢复：注雨 → debt 回落 → 地裂撤
4. T1 水毁：注大雨使 lowland soilMoisture>0.8 → 土堆切湿泥塌陷态 → 湿度回落后保持（锁存）→ 与 T2 塌洞并存不混

# 更改 2026-07-22（追加）：桑人岩画月亮——月轮图腾 + 朔望轮转

> 设计拍板（设计者，2026-07-22）：月相随 gameTime 轮转；轨迹由控制器按时间推算（无第二盏灯）；刻画词汇 = 点描月海/斑点（太阳的"光芒"语言不继承）。

## 为什么改

夜空此前只有星穹和银河，缺了夜里最重的那枚图腾。月亮按岩画语言补上：骨白点描盘 + 炭灰月海斑块，和银河是同一只手掷出来的灰。太阳的词汇是"光芒"（射线+刻环），月亮的词汇是"斑"——无射线、无光环，盘缘只有一线轻刻。

## 玩家视角

夜晚抬头有一轮会圆缺的月亮：跟着世界日历走，每月初一月亮完全消失（朔），月中满盘（望），上下弦各半月。月相和升起时刻自洽——新月时它跟着太阳走所以你看不见，满月时日落月升，上弦月黄昏挂在西天。月亮沉地平线时也会被远山吃掉下半盘，和太阳一样。满月夜里亮星绕开月盘，暴雨夜月和星一起隐入云层。

## 改动清单

| 文件 | 改动 |
|---|---|
| `Shaders/GlimmerSkyGradient.shader` | 月亮参数 7 个（`_MoonDir/_MoonPhase/_MoonTint/_MoonMariaCol/_MoonSize/_MoonGlow/_MoonEdgeRagged`）；新增 §3b 月轮图腾块：同太阳工艺（q/theta 极坐标、共用毛边、先凿后填、地平线遮挡），相位用 terminator 椭圆切弦（弦轴指向太阳投影，倾角物理正确），月海 = 低频 fbm 炭灰斑块；夜空块加"亮星不穿月"（`night *= 1 - moonOcc`）；头注补月亮段 |
| `Script/EmotionWeatherController.cs` | `moonGlowStrength` 字段；`UpdateSkybox` 末尾写月亮三参：相位 = `(世界历绝对日-1) % 30 / 30`（一月=一朔望月），方向 = 太阳轨道面时间平移 phase（朔时同日升落、望时日落月升），亮度 = `wNight × (1 - badT·stormStarHide)` |
| `Editor/GlimmerVisualSetup.cs` | 编辑态月亮默认值（`_MoonGlow=0` 不可见，Play 后由控制器接管） |

## 所有权表补行

| 字段 | 单写者 | 读者 |
|---|---|---|
| `_MoonDir` / `_MoonPhase` / `_MoonGlow` | EmotionWeatherController（UpdateSkybox，逐帧） | GlimmerSkyGradient shader（只读） |

## 边界与纪律

- 月相无状态：由 gameTime 绝对日推算，跨 session 自洽，catch-up 跳天后相位直接对齐
- 月亮不加第二盏方向光、不照亮场景——纯天穹图腾（L3 只读纪律；月光照明若要，是另一个设计决策）
- 无 WorldManager 的场景（验证/调参）：相位恒望、时刻取真实墙钟，不崩
- 轨迹 yaw 从真实太阳灯读（LightManager.SunDirection 单一事实来源），不另存副本

## 验证

1. 离线编译 0 错（IDE diagnostics 无 error）
2. Play 到夜晚：见骨白月盘 + 月海斑，亮度随 wNight 渐显
3. 改存档 gameTime.day 为 1（朔）→ 月亮消失；为 15（望）→ 满盘且日落月升
4. 暴雨：_MoonGlow 随 badT 遮蔽；月盘处星点被吃掉

## 修订（2026-07-22 play 实测后）：轨迹改中心对称 + 弦轴固定

**实测两个毛病**：① 月亮钉死在固定位置——轨迹经 `dayProgress` 推算，play 无 tick 时节律快照冻结在启动时刻，月亮不随太阳走；② 相位在太阳经过时"变换"——terminator 弦轴跟踪太阳投影，太阳相对月亮位置一变，弦的朝向跟着翻，读作圆缺乱跳。

**设计者拍板**：轨迹与太阳同角速度、方位中心对称。

- `EmotionWeatherController`：`_MoonDir = sun.transform.forward`（即 `-_SunDir`，太阳正对面）——直接镜像真实太阳灯，不再经 dayProgress 推算；日落月升、月落日升。相位仍取自世界日历，只改圆缺不改位置
- Shader §3b：terminator 弦轴从"指向太阳投影"改为**固定在月盘水平切轴**（盈亏镜像：上弦/下弦亮不同侧，`side = phase<0.5 ? 1 : -1`）；建基法与太阳图腾同款（world-up 参考叉积正交基）
- 一并收回调试用硬写（`dayProg=0.86`、`_MoonGlow=1`），`_MoonGlow` 恢复夜相×天气门控
